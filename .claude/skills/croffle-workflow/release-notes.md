# Release notes — `.ai/release/`

`.ai/release/<version>_<Release|Pre-Release>.md` holds the **release note body** that is posted to the GitHub Release. It is not a procedure document. The file is the exact text passed to `gh release edit --notes-file`.

## Titles

| Kind        | GitHub Release title            | File                                    |
| ----------- | ------------------------------- | --------------------------------------- |
| Stable      | `Croffle vX.Y.Z — Release Note` | `.ai/release/X.Y.Z_Release.md`          |
| Pre-release | `Pre-Release vX.Y.Z-rc.A`       | `.ai/release/X.Y.Z-rc.A_Pre-Release.md` |

## Changelogs section

The last section is always `## Changelogs` and is generated by GitHub:

```
gh api -X POST repos/team-croffle/croffle/releases/generate-notes \
  -f tag_name=vX.Y.Z-rc.A -f previous_tag_name=<previous tag> --jq .body
```

Paste the output as is, but rename its `## What's Changed` heading to `## Changelogs`. Keep everything else GitHub generated (PR list, `**Full Changelog**` link, contributor lines). `previous_tag_name` is the previous tag in semver order (for a stable release: the previous stable tag, so the list spans every rc).

The Korean block only says `- 하단 참조` under `## Changelog`; the English block carries the generated list.

## Publishing

The release workflow leaves the release as a **draft**. After the run succeeds:

```
gh release edit vX.Y.Z[-rc.A] --title "<title>" --notes-file .ai/release/<file> --draft=false [--prerelease]
```

Then verify with `gh release view <tag> --json name,isDraft,isPrerelease,assets`.

## Pre-release template — `X.Y.Z-rc.A_Pre-Release.md`

```
<details>
<summary>한국어 (Korean)</summary>

# Pre-Release vX.Y.Z-rc.A

버전 설명

## Overview

변경 요약

## Changelogs

- 하단 참조

</details>

---

# Pre-Release vX.Y.Z-rc.A

Summary of this version

## Overview

details of this version

## Changelogs

<GitHub generated, heading renamed>
```

Writing rules: Overview describes user-visible behaviour, not files. Mention PR numbers in Bug Fixes / Overview when helpful (`#84`). Include a "확인 요청 / Please verify" bullet when a change needs the user's manual check on a packaged build. Run URLs, commands, and QA logs do not belong here; they go to `.ai/history/` and `.ai/test/`.
