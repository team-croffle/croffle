## 문제
- **할 일(To-Do)이 없습니다.** 공개 로드맵 1.3 의 "마감 기준 할 일"이 아직 비어 있습니다. 2026-11-22 로드맵 재편으로 옛 1.3.4 에서 1.3.3 으로 앞당겼습니다. 사용자: "로드맵 재편안 허가.", "옛 브랜치는 지워. 다음 인텐트 열고". 공유는 서버 0.3.0 → 데스크톱 1.4.0 으로 갔습니다(요구분석 `.loctx/reports/1.3.3/requirements.md` v3).
  - 모델은 2026-10-20 에 사용자가 승인한 것을 따릅니다(계획 원본 `.loctx/context/plan/1.3.2_todo.md`, 당시 번호 1.3.2): 일정(Schedule)을 다시 쓰고 `kind: 'event' | 'todo'` 와 `completedAt` 을 더함, 마감은 `endDate`, **반복 할 일은 제외**(발생마다 완료 상태가 필요해서).
- **로그아웃하면 동기화 스위치가 꺼진 채 남습니다.** 로그아웃 때 바인딩과 함께 `enabled` 가 지워지고, 다시 로그인해도 꺼져 있습니다(`main/sync/sync-config.ts:31` `UNBOUND_STATE`). 2026-11-17 회고 P-6, 사용자: "다음 버전에서 유지하게 변경".
- **Claude Code hook 판별기가 파이썬이고 테스트가 없습니다.** 사용자: "변경을 다음 작업에 포함시켜.", "다음 세션에서 할거니까 테스트 코드 수정 관련 인계해놔"(2026-11-21, 인계 `.loctx/history/1.3.3.md`).
  - `.claude/hooks/bash_command.py` 는 셸 문법 해석(shlex)을 하던 때의 파이썬입니다. 지금은 JSON 읽기와 정규식만 남았고, 저장소의 다른 검사 스크립트(`scripts/check-*.mjs`)는 Node 입니다.
  - hook 판별기와 두 검사 스크립트(`scripts/check-spec-checks.mjs`, `scripts/check-design-commit-msg.mjs`)에 자동 테스트가 없습니다.

## 바라는 결과
- 일정 모달에서 **일정 / 할 일**을 고를 수 있습니다. 할 일은 제목 · 마감(날짜, 또는 날짜와 시각) · 설명 · 우선순위 · 색 · 태그 · 리마인더를 가집니다. 반복은 없습니다.
- 할 일은 **마감일에** 캘린더에 보이고, 완료 체크로 끝냅니다. 완료한 할 일은 취소선으로 남고, 다시 누르면 미완료로 돌아갑니다.
- 할 일의 리마인더는 **마감 기준**으로 울리고, 완료한 할 일은 울리지 않습니다. 일반 일정의 리마인더는 지금처럼 시작 기준입니다.
- 할 일은 가져오기 · 내보내기와 동기화에서 함께 다닙니다.
- 확장은 공개 타입의 `kind` · `completedAt`(선택 필드)으로 할 일을 구분할 수 있습니다. `@croffledev/croffle-types` minor 입니다.
- 로그아웃했다가 다시 로그인하면 동기화 스위치가 로그아웃 전 상태로 돌아옵니다.
- hook 판별기가 Node 로 바뀌고, 판별기와 두 검사 스크립트에 `node --test` 테스트가 생겨 CI 에서 돕니다. 판별 결과는 인계 문서의 "기대 결과 표"와 옮기기 전후로 같습니다.

## 계획
작업 순서입니다. 작업 단위(W-n)는 spec 에서 나눕니다.

1. **hook 판별기를 Node 로, 그리고 테스트** — 이 작업 중의 모든 Bash 명령이 이 hook 을 지나므로 먼저 합니다(PM 판단). 순서: 파이썬 판별기로 기대 결과 표의 사례를 돌려 원본 출력을 남김 → `.claude/hooks/bash-command.mjs`(판정 함수 export + CLI 진입부) → 같은 사례로 대조 → `pre-bash.sh` · `post-bash.sh` 의 호출 줄과 머리 주석을 마지막에 바꿈 → 파이썬 파일 삭제. 두 검사 스크립트의 테스트는 임시 git 저장소(`mkdtemp` + `git init`)에서 돕니다.
2. **동기화 스위치 유지** — 로그아웃 때 이전 `enabled` 를 남겨 두었다가 다시 로그인할 때 되살립니다.
3. **할 일 — 공개 타입과 데이터** — 공개 타입(`packages/types`)과 데스크톱 사본에 선택 필드 `kind` · `completedAt` 을 더하고 Changeset(minor)을 둡니다. 그다음 새 마이그레이션(0009: ADD COLUMN + 상수 기본값만, 백필 UPDATE 없음), 매퍼, 서비스 검증(만들기 · 고치기 · 합치기 세 곳), 가져오기 · 내보내기, 동기화 와이어를 고칩니다.
4. **할 일 — 리마인더** — 할 일은 마감 기준, 완료한 할 일은 후보에서 뺌. 되감기 창이 이미 지난 마감의 알림을 되살리지 않게 맞춥니다.
5. **할 일 — 화면** — 일정 모달의 종류 전환(할 일이면 반복 칸을 끄고 안내), 캘린더 표시와 완료 체크, 드래그로 마감 옮기기, 오른쪽 사이드바 표시(열린 질문 1). 화면은 `DESIGN.md` 를 따르고, 없는 규칙은 같은 변경에서 더합니다.
6. **문서** — README · README.ko, `packages/types/README.md`, 릴리스 노트(`.loctx/release/`).

머지 전 1차 감사 → 머지(사용자 지시) → `desktop-v1.3.3-rc.1` → 2차 감사 → 회고. stable 은 사용자 지시 때 냅니다. 1.3.2 rc.2 확인에서 결함이 나오면 1.3.2 안정화(rc.3)를 먼저 합니다. Changeset 이 만드는 `chore: version packages` PR 과 npm 스테이징도 이 루프의 일입니다.

## 제약
- 공개 타입의 새 필드는 **선택(optional)** 입니다. 필수로 만들면 major 가 됩니다.
- 커밋된 마이그레이션은 고치지 않습니다. 새 마이그레이션 뒤에 outbox 트리거가 그대로인지 확인합니다.
- 서버를 바꾸지 않습니다. 서버 0.2.0 은 행 내용을 그대로 저장하므로 새 열이 그대로 다닙니다.
- 렌더러는 Node API 를 쓰지 않고 preload/IPC 로 갑니다. 문구는 ko · en 카탈로그에 함께 넣습니다.
- hook 판별기의 동작은 바꾸지 않습니다(기대 결과 표가 기준). 예외는 "에이전트가 정한 것"의 다른 저장소 커밋 한 가지입니다. `.agents/harness/gates.yaml` · `.claude/settings.json` 은 reins 관리 파일이라 고치지 않습니다.
- 캘린더 고르기 · 팀 캘린더의 할 일은 1.4.0 입니다. 이번 할 일은 로컬 일정의 한 종류입니다(요구분석 v3 §13).

### 에이전트가 정한 것
- **종일 할 일의 마감 시각**: 마감일 0시를 기준으로 리마인더를 계산합니다(지금 종일 일정과 같은 방식, `common/reminder.ts:57` `toRemindAt`). 대안: 마감일 23:59. 이유: 2026-10-20 계획의 기본안이었고 종일 일정과 같은 규칙이 덜 헷갈립니다. "마감일 당일 0시 = 오늘 마감" 알림이 됩니다.
- **할 일의 저장 시각**: 화면에는 마감만 보이고, 저장할 때 시작과 끝을 둘 다 마감으로 둡니다. 대안: 시작 칸도 보임. 이유: 할 일에는 시작이 없고, 캘린더가 마감 칸 하나에 그리게 됩니다.
- **완료한 할 일**: 캘린더에 취소선으로 남고 숨기지 않습니다. 완료를 되돌려도 이미 울린 알림은 다시 울리지 않습니다(지금 알림 중복 방지 규칙 그대로).
- **할 일의 드래그**: 마감을 옮기고, 반복이 없으므로 "이 발생만 / 전체" 확인 창 없이 바로 옮깁니다.
- **동기화 중인 다른 기기가 1.3.2 이하일 때**: 옛 데스크톱은 `kind` · `completedAt` 열을 모르므로, 그 기기에서 할 일을 고치면 그 두 값이 빠진 채 올라가 모든 기기에서 일반 일정으로 바뀝니다. 서버는 행 내용을 통째로 바꾸므로 막을 수 없습니다. 릴리스 노트에 "동기화하는 모든 기기를 1.3.3 으로 올리십시오"를 적습니다. 대안: 서버가 모르는 열을 지키게 고침. 이유: 서버를 바꾸지 않는 버전이고, beta 입니다.
- **테스트 위치와 실행**: 판별기 · 검사 스크립트의 테스트를 `scripts/test/*.test.mjs` 에 두고, 루트 `package.json` 에 `test:repo`(`node --test scripts/test/`)를 둡니다. CI 의 Node 작업에서 `scripts/` · `.claude/hooks/` 가 바뀌었을 때 부릅니다. 대안: `pnpm -r test` 에 루트를 넣음. 이유: 그 게이트 명령은 reins 관리 파일(`gates.yaml`)에 있어 고칠 수 없고, 루트를 넣으면 데스크톱 테스트와 실행 범위가 섞입니다. 게이트에 넣는 일은 reins 쪽 항목으로 `.loctx/ROADMAP.local.md` 에 남깁니다.
- **다른 저장소에서 한 커밋도 게이트를 도는 hook 오작동**: 판별기를 옮기면서 커밋이 이 저장소 안의 것일 때만 게이트를 돌게 고치고, 테스트 사례로 남깁니다. 해로운 쪽이 아닌 동작 변경이라 PM 이 정했습니다.
- **브랜치**: `feat/desktop-1.3.3-todo`(`master` 에서). 공개 로드맵 재편 커밋(`5a04d58`)이 먼저 들어 있습니다.
