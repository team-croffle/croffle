# croffle-server v0.1.0-rc.1

Image: `ghcr.io/team-croffle/croffle-server:0.1.0-rc.1` · tag `server-v0.1.0-rc.1` · protocol `1`–`1`

The first preview of the optional self-hosted sync server for Croffle. It is one Go binary with one SQLite file, and it is published so the desktop 1.3.0 sync client can be built and tested against a real server. Nothing in the desktop app needs it: Croffle works fully without a server.

## Overview

- **Accounts and device tokens** — argon2id passwords; `POST /auth/login` issues an opaque token per device (only its hash is stored), `POST /auth/whoami` checks it. An OTP field is reserved.
- **Sync API** — `POST /sync/push` applies a batch of changes idempotently (`opId`) in one transaction and reports conflicts with the server's row (HTTP 200 + `conflicts[]`); `POST /sync/pull` serves the commit log from a cursor; `POST /sync/bootstrap` sends a paged snapshot to a new or stranded device.
- **Retention** — the commit log keeps 90 days; a cursor older than that gets 410 and the device re-bootstraps. Expired history and idempotency keys are swept daily.
- **Operator commands** — accounts, tokens, the team and the commit log, run against the database file.
- **Read-only dashboard** — sign in and see your own rows, embedded in the binary.
- **Hooks and a signed webhook** — observe commits from outside without changing them.
- `GET /health` reports the server version, the protocol range, database state, retention and the server clock.

## Upgrade notes

- First release: no upgrade path yet. Pin the image to `0.1.0-rc.1`; `:latest` does not move for a pre-release.
- Put TLS in front of it (Caddy, Traefik, nginx, an ingress). The server speaks plain HTTP and honours `X-Forwarded-*`.
- Setup and configuration: [apps/server/README.md](../../../apps/server/README.md).

## Compatibility

- Desktop 1.3.x (sync protocol 1). Desktop 1.3.0 is still in development; this preview exists to test it.

## Known limitations

- One team. Sharing cannot be undone yet; tags and reminders are not shared along with a schedule.
- Tokens do not expire (no refresh tokens yet).
- The dashboard is read-only; no metrics.
- Disabling an account blocks it but does not erase its data.
