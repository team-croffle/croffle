### 3. 사후 처리에서 추가된 지적

#### B-1. 리뷰 전 병합이 다시 발생했습니다 — 위반, 사후 리뷰 완료

`P/attempt-12/verify-sweep.mjs`는 `.fc-event`의 왼쪽 위 radius가 모두 10px인지 검사했습니다. 양 테마에서 `10px , 0px`로 실패한 뒤 attempt-13은 시작 조각의 왼쪽 위와 끝 조각의 오른쪽 위만 10px인지 검사하도록 변경했습니다. attempt-13 로그의 조각별 값은 이어지는 면이 0px이라는 설명을 뒷받침합니다.

그러나 spec V-8에는 달력 이벤트 `borderRadius === '10px'`가 그대로이고, 정정 7~9에는 이 예외가 없습니다. 생성된 날짜 선택 부품 내부의 예외를 메인 달력 이벤트 조각에 자동 적용할 수 없습니다. 기술적으로 타당한 해석일 수 있지만, 실패 뒤 기대값을 바꾸고 그 결과를 원래 기준의 충족으로 취급하는 절차는 test skill의 기준 보존 요구에 맞지 않습니다. 변경이 공개되었으므로 은폐로 판정하지는 않습니다.

**해결 방법:** 기존 실패와 변경 소스를 보존한 채 조각별 기준의 해석을 PL 또는 검사 설계자가 확인하고, spec 정정이 필요하면 사용자에게 해당 변경의 사후 수용 또는 수정 결정을 받아야 합니다. 단일 날짜 fixture의 원래 기준 검사와 자정을 넘는 사례를 구분하여 증적을 남기는 방법도 가능합니다. 이미 바꾼 기대값을 처음부터 승인된 기준으로 기록해서는 안 됩니다.

#### D-2. #124의 조건부 병합 허가에서 요구한 설명이 병합 뒤에 이루어졌습니다 — 위반 확인

H의 사용자 원문은 “만약 직접 재기 어려우면 사유를 설명하고 병합해.”입니다. 새 H 기록은 설명이 병합 뒤였다고 명시합니다. 따라서 B-4의 해당 부분은 확인 불가에서 순서 미준수로 바뀝니다.

“1번은 수용은 할게 그럼.”은 기록상 B-1의 리뷰 전 병합에 대한 수용입니다. 이를 별개인 설명 순서 문제의 수용까지 확대할 근거는 없습니다. 다만 #124 병합 자체에 아무 허가도 없었다고 판정하는 것은 아닙니다.

**해결 방법:** 사후 설명 사실을 유지하고 이 조건 미이행을 사용자에게 보고하여 수용 또는 추가 조치 결정을 기록해야 합니다. 당시 실행 원본이 없는 브랜치 정리 정보는 계속 사후 기록으로 표시해야 합니다.

#### D-3. #125 이후 최종 판정과 사용자 결정의 기록 통합이 미완료입니다 — 기록 보완 필요

H와 #125 spec에는 새로운 결정과 수정이 있지만 `P/report.md`의 최종 상태표는 이전 상태입니다. 설정 오류 화면의 검사 생략 수용도 intent의 waiver에 반영되지 않았습니다. 감사 파일은 현재 미커밋이고, 합의된 재발 방지 knowledge 노트도 확인되지 않습니다.

이는 #125의 승인이나 코드 변경이 무효라는 뜻이 아닙니다. 다만 현재 표만으로는 어떤 조건이 측정으로 충족되었고, 어떤 조건이 사용자 결정으로 제외되었으며, 무엇이 아직 열려 있는지 최종적으로 판단하기 어렵습니다.

**해결 방법:** attempt-14~16과 사용자 결정을 반영한 대응표를 추가하고, 기존 표는 당시 상태로 보존해야 합니다. 이미 받은 승인은 다시 요구하지 말고 정확한 범위로 기록해야 합니다. 남은 B-2·A-3 및 D-1·D-2는 수정하거나 사용자 수용을 받아 구분하고, 필요한 waiver와 합의된 재발 방지 기록을 감사 결정과 함께 커밋해야 합니다.

### 5. 결론

#125는 기록상 승인된 정정과 구현이 함께 커밋되었고 병합 전 지정 리뷰, 변경 범위의 CI, 병합 허가와 브랜치 정리가 확인됩니다. A-1·B-1의 순서 위반이 #125에서 반복되었다는 근거는 없습니다. 다만 보완 검사 집계가 곧 전체 V-7·V-8·V-9 충족은 아니며, 남은 B-2·A-3 범위와 D-1의 기대값 변경, D-2의 조건부 허가 이행 문제는 아직 최종 처리되지 않았습니다. rc 전에 PM이 이 잔여 사항을 보고하고 사용자가 수정 또는 수용을 결정해야 하며, 이미 확인된 수용은 다시 묻지 않고 최종 대응표·필요한 waiver·재발 방지 기록과 함께 감사 기록에 반영하여 커밋해야 합니다. 그 절차가 끝나기 전에는 감사 처리 완료로 판정할 수 없습니다.
