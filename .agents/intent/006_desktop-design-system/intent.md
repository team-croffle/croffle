## 문제
데스크톱 1.3.1 의 화면에는 아래 문제가 있습니다(2026-11-19 디자인 세션, 인계 `.loctx/history/1.3.2.md`).

- **대비가 낮습니다.** 강조색 위 흰 글자가 약 2:1 입니다(주 버튼 · 스위치 · 확인 창 버튼 · 사이드바 선택 항목). 1.3.0-rc.2 에서 `--primary` 를 강조색에 연결하면서 넓어졌고, intent 002 에서 미뤘습니다. 입력칸 테두리, 다크 표면 순서, 우선순위 배지의 색도 같은 계열의 문제입니다.
- **토큰이 제품마다 따로입니다.** Croffle 데스크톱(`apps/desktop/src/renderer/src/index.css`)과 pipit-hub 의 색 · 반경 · 그림자가 다릅니다. 사용자는 이를 하나로 합쳐 디자인 시스템 "croffle"(테마 Croffle Light / Croffle Dark)을 만들었습니다.
- **만들다 만 동작과 어긋난 문구가 있습니다.** 코드에서 확인한 것(PM):
  - 알림(종) 버튼에 클릭 동작이 없습니다(`left-sidebar.vue:157–163`).
  - 오른쪽 사이드바 "다가오는 일정"은 늘 빈 상태 문구만 보입니다(`right-sidebar.vue:190–200`).
  - 확장 삭제 확인이 브라우저 `confirm()` 입니다(`settings-modal.vue:268`).
  - 설정은 저장 · 취소 푸터로 적용합니다(`settings-modal.vue:310–346`, 1233–1237).
  - ko 카탈로그의 `settings.errors.install` · `installLocal` 이 영어 문장입니다(`ko.json:171–172`).
  - 업데이트는 시작할 때 자동 확인만 있고 수동으로 확인할 방법이 없습니다(`main/index.ts:158–160`).

공유(1.3.3) · 할 일(1.3.4) 화면을 옛 토큰으로 만들고 다시 고치는 이중 작업을 피하려고 이 버전을 앞에 끼웠습니다. 2026-11-19 PM 제안에 사용자: "아 그래?? 그러면 그대로 할건데".

## 계획
작업 순서입니다. 작업 단위(W-n)는 spec 에서 나눕니다.

1. **토큰** — `index.css` 를 통합 토큰으로 바꿉니다. `--croffle-*` 는 새 토큰의 별칭으로 남깁니다. 반경은 12px 기준(control 10 / surface 16)이고, 그림자는 4종입니다. 강조 색상 설정(`appearance.ts`, `--croffle-accent-hue`)은 강조색 계열(primary · 강조 글자 · 링 · 오늘 표시)만 바꿉니다. 다른 일이 모두 이 위에 올라가므로 먼저 합니다.
2. **대비 · 색 규칙** — 강조색 위 글자, 강조 글자 토큰, 입력칸 테두리 3:1, 다크 표면 순서, 우선순위 배지를 상태 토큰으로, 오류 글자 규칙을 화면 전반에 적용합니다.
3. **셸 동작** — 알림 팝오버, 다가오는 일정, 제목 표시줄 테마 좌클릭 저장, 사이드바 부제(예: "오늘 일정 N개"), 버전 타일 → 정보 · 업데이트 확인 팝오버.
4. **설정 · 업데이트** — 설정 바로 적용(저장/취소 푸터 제거), 확장 삭제를 앱 확인 모달로, 수동 업데이트 확인(설정 › 일반 › 업데이트; IPC 를 새로 둠), 도움말 문구, ko 카탈로그의 영어 오류 문구 번역.
5. **문서** — `DESIGN.md` 갱신. 앰버 예외를 없애고 `warning` 토큰으로 바꾸며, "Do not rename them or change their values" 규칙을 "이름은 유지, 값은 새 토큰을 따름"으로 고칩니다. 릴리스 노트는 `.loctx/release/` 에 씁니다.

머지 뒤 audit → `desktop-v1.3.2-rc.1` 입니다. stable 은 사용자 지시 때 냅니다.

## 영향 범위
- `apps/desktop/src/renderer/**` — `index.css`, 셸 · 사이드바 · 설정 · 모달 컴포넌트. `components/ui/**` 는 생성된 shadcn-vue 코드라 토큰을 통해서만 바뀌게 하고, 고쳐야 하면 spec 에 적습니다(PM 해석).
- `apps/desktop/src/main/**` · `src/preload/**` — 수동 업데이트 확인 IPC. 다가오는 일정 · 알림 목록에 새 조회가 필요하면 그 IPC 도 여기에 둡니다.
- `apps/desktop/src/common/i18n/locales/{ko,en}.json`.
- `apps/desktop/DESIGN.md`, `apps/desktop/test/**`.
- 영향 없음(PM 해석): `apps/server/**`, `packages/types` · `packages/cli`(새 공개 API 를 두지 않으면 Changeset 도 없음), DB 스키마.

## 제약
- 확장이 읽는 `--croffle-*` 이름은 지우거나 바꾸지 않습니다. 값이 바뀌므로 확장 화면의 색도 바뀝니다. 이를 릴리스 노트에 적습니다.
- 렌더러는 Node API 를 쓰지 않고 preload/IPC 로 갑니다. 새 IPC 는 `ipc/*.handler.ts` → `preload/api/**` 순서이고, 공개 타입이 필요할 때만 `packages/types` 를 고칩니다.
- 문구는 ko · en 카탈로그에 함께 넣습니다. 렌더러 전용 locale 트리를 두지 않습니다.
- 디자인 시스템 · 캔버스 아티팩트는 기준으로 읽기만 합니다. 시스템을 고쳐야 하면 사용자에게 먼저 묻습니다.
- pipit-hub(pipit-bot) 반영은 이 작업이 아닙니다(사용자: "각 저장소 pipit은 알아서 할게").
- 서버 WebUI 디자인은 서버 0.3.1 입니다.

### 에이전트가 정한 것
- **다가오는 일정의 범위**: 지금부터 7일 안의 일정을 최대 5개 보여 주고, 반복 일정은 펼친 발생으로 셉니다. 대안: 개수만(다음 5개). 이유: 오른쪽 사이드바 칸이 작고, 먼 일정은 달력에서 봅니다. 사용자가 다르게 원하면 바꿉니다.
- **설정 바로 적용의 범위**: 스위치 · 선택은 바꾸는 즉시, 글자 입력칸(예: 동기화 서버 주소)은 칸을 벗어나거나 Enter 를 눌렀을 때 적용합니다. 대안: 입력칸만 확인 버튼을 둠. 이유: 타자 중간에 적용되면 잘못된 값이 저장됩니다.
- **사이드바 부제**: "오늘 일정 N개"(없으면 "오늘 일정 없음"). 대안: 날짜. 이유: 날짜는 달력 머리글에 이미 있습니다.
- **수동 업데이트 확인의 결과 표시**: "최신 버전입니다" / "새 버전 X 가 있습니다"(기존 업데이트 모달로 연결) / 오류. 개발 빌드에서는 버튼을 끕니다. 대안: 결과를 토스트로만. 이유: 버전 타일 팝오버와 설정 두 곳에서 같은 상태를 보여야 합니다.
- **브랜치**: `feat/desktop-1.3.2-design-system`(`master` 에서).
