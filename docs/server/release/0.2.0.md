# croffle-server v0.2.0

Image: `ghcr.io/team-croffle/croffle-server:0.2.0` (also `:latest`) · tag `server-v0.2.0` · protocol `1`–`1`

The self-hosted sync server (beta) gets a dashboard for whoever runs it, several teams, and encrypted one-time code secrets. An operator can now do in the browser everything the command line does: accounts, device tokens, teams, and the server itself. Protocol 1 is unchanged: desktop 1.3.0 and 1.3.1 keep syncing without an update, including when their account joins a new team.

## Overview

- **Operators and the operator screens** — an account can be an operator (`user create --operator`, `user operator grant`, or from the dashboard). Operators see four more dashboard tabs: **Accounts** (create, disable and enable, reset a password, turn off one-time codes, make or remove operators), **All devices** (every device; issue a token shown once, revoke), **Manage teams** (create, rename, add and remove members) and **Server** (database facts, vacuum, the commit log of every account without row contents). Every operator request is checked again, each action leaves an `operator action` log line without secrets, and the last active operator cannot be removed or disabled from the dashboard.
- **Several teams** — operators create and rename teams and move accounts in and out, from the dashboard or with `team create`, `team rename`, `team members`, `team remove-member`. When an account joins a team, each of its devices receives the team's earlier rows: its next pull is answered with `410 cursor_too_old` (`details.reason: "team_scope"`), which desktop 1.3.x already turns into one fresh snapshot. When an account leaves, the team's rows stop reaching it and changes to them are refused (`403 foreign_team`).
- **Encrypted one-time code secrets** — with `CROFFLE_SECRET_KEY` or `CROFFLE_SECRET_KEY_FILE` (32 bytes, base64; `secret generate` makes one) the TOTP secrets are stored encrypted (AES-256-GCM, bound to the account). Existing secrets are encrypted at the next start; nobody sets codes up again. `secret rotate` re-encrypts them with a new key. Without a key the server works as before and warns at start-up and on the operator screens.
- `db info` and the **Server** tab report the key state and how many secrets are plain or encrypted. `GET /health` lists the new `team-scopes` feature.
- The login answer's single `teamId` stays `team-default` for an account that is in it, whatever other teams it joins.

## Upgrade notes

- Change the image tag to `0.2.0`. Two migrations run at start-up: 0006 (operators) and 0007 (team scopes). **No device takes a new snapshot because of the upgrade**; every existing device is taken as up to date for the teams its account is in.
- **Name an operator** to use the new screens: `docker compose exec croffle-server croffle-server user operator grant <you>`. Until then the dashboard looks as it did.
- **Set a secret key** if any account uses one-time codes, and keep the key outside the database volume and backed up separately (see "Secret key" in the server README). If the key is later lost or replaced by another one, the server refuses to start rather than locking those accounts out; `user otp disable` (which needs no key) is the way out.
- New settings, both optional: `CROFFLE_SECRET_KEY`, `CROFFLE_SECRET_KEY_FILE` (set one, not both).
- A device that joined a team under 0.1.x without taking a snapshot afterwards may have missed that team's older rows; the upgrade does not repair that. Revoke the device and sign in on it again to give it a fresh snapshot.
- No new dependency: the encryption uses the Go standard library.

## Compatibility

- Desktop 1.3.x (sync protocol 1), unchanged. Joining a team works with desktop 1.3.0 and 1.3.1 through their existing snapshot fallback. The operator screens are in the server's dashboard; the desktop app does not manage teams.

## Known limitations

- Beta. Sharing cannot be undone yet; members cannot invite others or leave a team themselves; teams cannot be deleted; tags and reminders are not shared along with a schedule.
- Joining a team sends each of the account's devices to one full snapshot.
- Disabling an account blocks it but does not erase its data.

# croffle-server v0.2.0

셀프호스트 동기화 서버(beta)에 운영자를 위한 대시보드, 여러 팀, 암호화된 일회용 코드 secret 이 생겼습니다. 운영자는 이제 명령으로 하던 일을 모두 브라우저에서 할 수 있습니다: 계정, 기기 토큰, 팀, 서버 자체. 프로토콜 1 은 그대로라서 데스크톱 1.3.0 · 1.3.1 은 업데이트 없이 계속 동기화되고, 계정이 새 팀에 들어갈 때도 그렇습니다.

## 변경 사항

- **운영자와 운영 화면** — 계정을 운영자로 둘 수 있습니다(`user create --operator`, `user operator grant`, 또는 대시보드). 운영자에게는 대시보드 탭이 넷 더 보입니다: **Accounts**(만들기, 비활성화 · 활성화, 비밀번호 재설정, 일회용 코드 끄기, 운영자 지정 · 해제), **All devices**(모든 기기, 한 번만 보여 주는 토큰 발급, 회수), **Manage teams**(만들기, 이름 바꾸기, 멤버 추가 · 제거), **Server**(데이터베이스 정보, vacuum, 행 내용 없는 모든 계정의 커밋 로그). 운영 요청은 매번 다시 확인하고, 작업마다 비밀 값 없는 `operator action` 로그를 한 줄 남기며, 마지막 활성 운영자는 대시보드에서 해제하거나 비활성화할 수 없습니다.
- **여러 팀** — 운영자가 대시보드나 `team create`, `team rename`, `team members`, `team remove-member` 로 팀을 만들고 이름을 바꾸고 계정을 넣고 뺍니다. 계정이 팀에 들어가면 그 계정의 기기마다 팀의 예전 행을 받습니다. 다음 pull 에 서버가 `410 cursor_too_old`(`details.reason: "team_scope"`)로 답하고, 데스크톱 1.3.x 는 이미 이를 스냅샷 한 번으로 처리합니다. 팀에서 빠지면 그 팀의 행은 더 가지 않고, 그 행의 변경은 거부합니다(`403 foreign_team`).
- **일회용 코드 secret 암호화** — `CROFFLE_SECRET_KEY` 또는 `CROFFLE_SECRET_KEY_FILE`(32바이트 base64, `secret generate` 로 만듦)을 주면 TOTP secret 을 암호화해 저장합니다(AES-256-GCM, 계정에 묶임). 기존 secret 은 다음 시작 때 암호화되고, 아무도 코드를 다시 등록하지 않습니다. `secret rotate` 로 새 키로 다시 암호화합니다. 키가 없으면 예전처럼 동작하되 시작 로그와 운영 화면에서 경고합니다.
- `db info` 와 **Server** 탭이 키 상태와 평문 · 암호화 secret 개수를 보여 줍니다. `GET /health` 가 새 기능 `team-scopes` 를 알려 줍니다.
- 로그인 응답의 단일 `teamId` 는 계정이 `team-default` 에 있으면 다른 팀에 들어가도 `team-default` 로 유지됩니다.

## 업그레이드 안내

- 이미지 태그를 `0.2.0` 으로 바꾸면 됩니다. 시작할 때 마이그레이션 두 개가 돕니다: 0006(운영자), 0007(팀 범위). **업그레이드 때문에 스냅샷을 다시 받는 기기는 없습니다.** 기존 기기는 모두 그 계정이 속한 팀을 이미 받은 것으로 봅니다.
- 새 화면을 쓰려면 **운영자를 지정하십시오**: `docker compose exec croffle-server croffle-server user operator grant <나>`. 그 전까지 대시보드는 예전과 같습니다.
- 일회용 코드를 쓰는 계정이 있다면 **비밀 키를 설정하고**, 키는 데이터베이스 볼륨 밖에 두고 따로 백업하십시오(서버 README 의 "비밀 키" 참고). 나중에 키를 잃거나 다른 키로 바뀌면 서버는 그 계정들을 막는 대신 시작을 거부합니다. 키 없이 되는 `user otp disable` 이 빠져나갈 길입니다.
- 새 설정은 둘 다 선택입니다: `CROFFLE_SECRET_KEY`, `CROFFLE_SECRET_KEY_FILE`(둘 중 하나만).
- 0.1.x 에서 팀에 들어간 뒤 스냅샷을 다시 받지 않은 기기는 그 팀의 예전 행을 놓쳤을 수 있고, 업그레이드가 이를 고치지는 않습니다. 그 기기를 회수하고 다시 로그인하면 스냅샷을 새로 받습니다.
- 새 의존성은 없습니다. 암호화는 Go 표준 라이브러리로 합니다.

## 호환

- 데스크톱 1.3.x(동기화 프로토콜 1), 변경 없음. 팀 합류는 데스크톱 1.3.0 · 1.3.1 의 기존 스냅샷 처리로 동작합니다. 운영 화면은 서버 대시보드에 있고, 데스크톱 앱은 팀을 관리하지 않습니다.

## 알려진 한계

- beta 입니다. 공유 취소가 아직 없고, 멤버가 직접 초대하거나 팀을 나갈 수 없으며, 팀은 지울 수 없고, 태그 · 리마인더는 일정과 함께 공유되지 않습니다.
- 팀에 들어가면 그 계정의 기기마다 전체 스냅샷을 한 번 받습니다.
- 계정을 비활성화하면 접속은 막히지만 데이터는 지워지지 않습니다.
