# croffle-server v0.1.1

Image: `ghcr.io/team-croffle/croffle-server:0.1.1` · tag `server-v0.1.1` · protocol `1`–`1`

Mature authentication and better operator visibility for the self-hosted sync server (beta). Accounts can require one-time codes, a new endpoint issues renewable access/refresh token pairs, device tokens can optionally expire, push conflicts name the fields that differ, and metrics can be switched on. Protocol 1 is unchanged: desktop 1.3.0 keeps syncing without an update.

## Overview

- **One-time codes (TOTP)** — an account turns them on in the dashboard (**Security**: QR code, confirm with a code, ten recovery codes shown once). From then on every sign-in — desktop, `POST /auth/token`, dashboard — needs a code or a recovery code; without one the server answers `401 otp_required`, which desktop 1.3.0 already handles. Codes cannot be replayed and recovery codes work once. Operators can remove codes with `user otp disable`.
- **Access/refresh token pairs** — `POST /auth/token` (`grantType` `password` or `refresh_token`) issues a short-lived access token (15 minutes) and a refresh token (30 days, restarted at each refresh). A refresh token works once; presenting a spent one again revokes every token from that sign-in. Sync endpoints accept access tokens and device tokens, never refresh tokens. The desktop does not use this endpoint yet.
- **Optional device token expiry** — `CROFFLE_DEVICE_TOKEN_TTL` (default: never). Only tokens issued by a sign-in after it is set expire; `token issue --expires-in` / `--no-expiry` choose per token, and `token list` and the dashboard show the expiry.
- **Conflict details** — each push conflict carries `differentFields`, the fields whose values differ between the commit and the server row. Information only: the server still applies nothing on a conflict and the client still settles with last-writer-wins.
- **Metrics** — `CROFFLE_METRICS_LISTEN` opens a separate listener with Prometheus `GET /metrics`: requests and latency by route, push/pull/bootstrap volume, sign-in attempts by result, refresh reuse. Off by default, never on the API listener, no account or address in any label.
- **Dashboard** — revoke your own devices; requests that change state are refused from other origins (`CROFFLE_DASH_TRUSTED_ORIGINS` adds origins for a proxy that rewrites `Host`). Revoking a device now stops its access and refresh tokens too.
- **Fix: `--password-stdin` on a terminal** — it now prompts, reads one hidden line and stops at Enter, instead of waiting for end-of-input (which never came in Windows Git Bash). Pipes work as before. Use `docker exec -it` (or `winpty docker exec -it` in Git Bash).
- `GET /health` lists the optional features: `conflict-fields`, `device-token-ttl`, `token-pair`, `totp`.
- The login rate limit and the TOTP and metrics code now come from established libraries (`golang.org/x/time/rate`, `github.com/pquerna/otp`, `github.com/prometheus/client_golang`); the server README lists every dependency.

## Upgrade notes

- Change the image tag to `0.1.1`. Two migrations (0004 tokens, 0005 one-time codes) run at start-up; existing passwords and device tokens keep working and do not expire.
- New settings, all optional and off or defaulted: `CROFFLE_DEVICE_TOKEN_TTL`, `CROFFLE_ACCESS_TOKEN_TTL`, `CROFFLE_REFRESH_TOKEN_TTL`, `CROFFLE_METRICS_LISTEN`, `CROFFLE_DASH_TRUSTED_ORIGINS`. With none set, the server behaves as 0.1.0 did, plus the new endpoints.
- **Setting `CROFFLE_DEVICE_TOKEN_TTL` makes desktop 1.3.0 sign in again each time a token expires**, because 1.3.0 does not use refresh tokens. Leave it unset unless you want that.
- If you enable metrics, publish the metrics port to a private network only; it has no authentication.
- The `retention_swept` webhook payload gains `deletedTokens`.
- The binary is about 2.8 MB larger (the metrics library): 11.8 MB → 14.6 MB stripped, linux/amd64.

## Compatibility

- Desktop 1.3.x (sync protocol 1), unchanged. One-time codes work with desktop 1.3.0 through its existing code prompt. Token pairs and `differentFields` are not used by the desktop yet.

## Known limitations

- Beta: one team. Sharing cannot be undone yet; tags and reminders are not shared along with a schedule.
- One-time code secrets are stored unencrypted in the database (recovery codes only as hashes); encryption is planned for 0.2.0.
- Disabling an account blocks it but does not erase its data.

# croffle-server v0.1.1

셀프호스트 동기화 서버(beta)의 인증을 성숙한 방식으로 바꾸고 운영자가 볼 수 있는 것을 늘린 릴리스입니다. 계정에 일회용 코드를 걸 수 있고, 갱신되는 access/refresh 토큰 쌍을 발급하는 엔드포인트가 생겼으며, 기기 토큰에 만료를 걸 수 있고, push 충돌이 어느 필드가 다른지 알려 주며, metrics 를 켤 수 있습니다. 프로토콜 1 은 그대로라서 데스크톱 1.3.0 은 업데이트 없이 계속 동기화됩니다.

## 변경 사항

- **일회용 코드(TOTP)** — 계정이 대시보드의 **Security** 에서 켭니다(QR 코드, 코드로 확인, 한 번만 보여주는 복구 코드 10개). 그 뒤로는 데스크톱 · `POST /auth/token` · 대시보드의 모든 로그인에 코드나 복구 코드가 필요하고, 없으면 `401 otp_required` 를 돌려줍니다. 데스크톱 1.3.0 은 이미 이를 처리합니다. 코드는 재사용할 수 없고 복구 코드는 한 번만 씁니다. 운영자는 `user otp disable` 로 풀 수 있습니다.
- **access/refresh 토큰 쌍** — `POST /auth/token`(`grantType` `password` 또는 `refresh_token`)이 짧은 access token(15분)과 refresh token(30일, 갱신마다 다시 계산)을 줍니다. refresh token 은 한 번만 쓰고, 이미 쓴 것을 다시 내밀면 그 로그인에서 나온 토큰을 모두 회수합니다. 동기화 엔드포인트는 access token 과 기기 토큰을 받고 refresh token 은 받지 않습니다. 데스크톱은 아직 이 엔드포인트를 쓰지 않습니다.
- **기기 토큰 만료(선택)** — `CROFFLE_DEVICE_TOKEN_TTL`(기본: 만료 없음). 켠 뒤 로그인으로 발급하는 토큰만 만료됩니다. `token issue --expires-in` / `--no-expiry` 로 토큰마다 정할 수 있고, `token list` 와 대시보드에 만료가 보입니다.
- **충돌 상세** — push 충돌마다 `differentFields`(보낸 행과 서버 행에서 값이 다른 필드)가 붙습니다. 정보일 뿐이고, 서버는 여전히 충돌 때 아무것도 적용하지 않으며 승자는 클라이언트가 last-writer-wins 로 정합니다.
- **metrics** — `CROFFLE_METRICS_LISTEN` 을 주면 별도 주소에서 Prometheus `GET /metrics` 를 엽니다. 라우트별 요청 수 · 지연, push/pull/bootstrap 양, 결과별 로그인 시도, refresh 재사용을 셉니다. 기본은 꺼짐이고, API 주소에는 없으며, 계정이나 주소가 라벨에 들어가지 않습니다.
- **대시보드** — 자기 기기를 회수할 수 있습니다. 상태를 바꾸는 요청은 다른 출처에서 오면 거부합니다(`Host` 를 바꾸는 프록시는 `CROFFLE_DASH_TRUSTED_ORIGINS` 로 출처를 더합니다). 기기를 회수하면 그 기기의 access · refresh 토큰도 멈춥니다.
- **수정: 터미널에서 `--password-stdin`** — 이제 `Password:` 를 띄우고 화면에 보이지 않게 한 줄을 읽어 Enter 에서 끝납니다. 예전에는 입력 끝(EOF)을 기다려서 Windows Git Bash 에서는 끝나지 않았습니다. 파이프는 예전과 같습니다. `docker exec -it`(Git Bash 는 `winpty docker exec -it`)를 쓰십시오.
- `GET /health` 가 선택 기능 `conflict-fields`, `device-token-ttl`, `token-pair`, `totp` 를 알려 줍니다.
- 로그인 rate limit, TOTP, metrics 는 검증된 라이브러리(`golang.org/x/time/rate`, `github.com/pquerna/otp`, `github.com/prometheus/client_golang`)를 씁니다. 서버 README 에 의존성 목록이 있습니다.

## 업그레이드 안내

- 이미지 태그를 `0.1.1` 로 바꾸면 됩니다. 시작할 때 마이그레이션 두 개(0004 토큰, 0005 일회용 코드)가 돌고, 기존 비밀번호와 기기 토큰은 그대로 동작하며 만료되지 않습니다.
- 새 설정은 모두 선택이고 꺼짐이거나 기본값이 있습니다: `CROFFLE_DEVICE_TOKEN_TTL`, `CROFFLE_ACCESS_TOKEN_TTL`, `CROFFLE_REFRESH_TOKEN_TTL`, `CROFFLE_METRICS_LISTEN`, `CROFFLE_DASH_TRUSTED_ORIGINS`. 아무것도 주지 않으면 새 엔드포인트가 더해진 것 말고는 0.1.0 과 같게 동작합니다.
- **`CROFFLE_DEVICE_TOKEN_TTL` 을 켜면 데스크톱 1.3.0 은 토큰이 만료될 때마다 다시 로그인해야 합니다.** 1.3.0 은 refresh token 을 쓰지 않기 때문입니다. 원하지 않으면 비워 두십시오.
- metrics 를 켜면 그 포트는 내부망에만 공개하십시오. 자체 인증이 없습니다.
- `retention_swept` 웹훅 본문에 `deletedTokens` 가 더해졌습니다.
- 바이너리가 약 2.8 MB 커졌습니다(metrics 라이브러리): strip 기준 linux/amd64 11.8 MB → 14.6 MB.

## 호환

- 데스크톱 1.3.x(동기화 프로토콜 1), 변경 없음. 일회용 코드는 데스크톱 1.3.0 의 기존 코드 입력으로 동작합니다. 토큰 쌍과 `differentFields` 는 데스크톱이 아직 쓰지 않습니다.

## 알려진 한계

- beta 입니다. 팀은 하나뿐이고, 공유 취소와 태그 · 리마인더 동반 공유는 아직 없습니다.
- 일회용 코드 secret 은 데이터베이스에 암호화하지 않고 저장합니다(복구 코드는 해시만). 암호화는 0.2.0 에 넣을 예정입니다.
- 계정을 비활성화하면 접속은 막히지만 데이터는 지워지지 않습니다.
