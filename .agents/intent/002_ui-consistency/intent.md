## 문제
데스크톱 화면의 버튼 · 입력 · 다이얼로그가 화면마다 크기와 모양이 다릅니다. 1.3.0-rc.1 을 본 뒤 사용자가 지적했습니다.

사용자 요청 (2026-11-12):
- "UI를 분석해서, 버튼의 너비, 크기, round 값, input 너비 등등 일관성 없는 거 전부 찾아내."
- "일관성 있는 디자인 시스템을 만들어두고, 향후 계속 참고할 것."
- 로컬 로드맵의 rc.2 항목: "설정 창 저장/취소 버튼 너비가 다른 것 등 사용자 지적 사항"

조사 결과 불일치는 36건입니다 (버튼 9 · 입력 7 · radius 5 · 다이얼로그/카드 5 · 글자/아이콘 5 · 색 5). 기본 부품(`components/ui`)은 일관되고, 불일치는 전부 화면에서 class 로 덮어쓴 곳에서 생깁니다. 뿌리는 세 가지입니다 (PM 해석).

1. 강조색 버튼 variant 가 없어 화면마다 색을 손으로 칠합니다. "주 버튼"이 강조색 · 고정 갈색(`#A68A64`, 강조색 설정을 따라가지 않음) · 검정 세 가지입니다.
2. 컨트롤 높이 기준이 없어 36 / 38 / 40 / 44px 가 섞여 있습니다.
3. `Button` · `Input` 대신 `<button>` · `<input>` 을 직접 쓴 곳이 22군데입니다.

## 바라는 결과
- 같은 역할의 컨트롤은 어느 화면에서나 같은 높이 · radius · 색 · 포커스 링을 갖습니다.
- 설정 창 취소 / 저장 버튼의 너비와 굵기가 같습니다.
- 규칙이 문서 하나에 적혀 있고, 이후 UI 작업(사람 · 에이전트)이 그 문서를 따릅니다.
- 강조색 설정을 바꾸면 모든 주 버튼 · 스위치 · 포커스 링이 함께 바뀝니다.
- 기능과 문구는 바뀌지 않습니다.

## 계획
1. **디자인 시스템 문서** — `apps/desktop/DESIGN.md` (영어, 커밋). 아래 "제안하는 규칙"을 옮기고, AGENTS.md 의 Conventions 에 한 줄로 가리킵니다.
2. **토큰 연결** — `index.css` 에서 `--primary` · `--primary-foreground` · `--ring` · `--border` · `--input` 을 croffle 토큰에 연결합니다. 화면의 색 덮어쓰기(`bg-croffle-primary …`, `#A68A64`, `border-croffle-border`, `ring-croffle-primary/30`)가 필요 없어집니다.
3. **버튼** — 높이 · 패딩 · 굵기 덮어쓰기를 지우고 variant / size 만 씁니다. `<button>` 을 `Button` 으로 바꿉니다. 푸터 버튼에 최소 너비를 줍니다.
4. **입력 · 선택** — `<input>` 을 `Input` 으로 바꾸고 높이 덮어쓰기를 지웁니다. 설정 창의 선택 상자 폭을 정합니다.
5. **다이얼로그 · 카드 · radius** — 폭 · 푸터 · 그림자 · radius 를 규칙에 맞춥니다.
6. **글자 · 색 정리** — 라벨 굵기, 죽은 class(`text-croffle-text-dark`, `hover:bg-opacity-90`), `neutral-*` 직접 사용을 토큰으로 바꿉니다. `config-schema-form.vue:47` 의 다크 모드 글자색을 고칩니다.
7. **확인** — 라이트 / 다크 각각에서 주요 화면(달력, 일정 모달 보기 · 편집, 설정 탭 전부, 확인 · 도움말 · 업데이트 모달) 스크린샷을 전후로 남겨 비교합니다.

머지 뒤 audit → `desktop-v1.3.0-rc.2` 입니다.

### 제안하는 규칙
| 항목 | 규칙 | 지금 |
|---|---|---|
| 컨트롤 높이 | 버튼 · 입력 · 선택 모두 **36px** (`h-9`, 부품 기본값). 조밀한 칩 · 토글은 32px (`size="sm"`) | 36 / 38 / 40 / 44 |
| 아이콘 버튼 | 본문 32px (`icon-sm`), 사이드바 레일 36px (`icon`), 제목 표시줄 28px | 24 / 28 / 32 / 36 |
| radius | 컨트롤 8px (`rounded-md`) · 표면(카드, 다이얼로그, 패널) 14px (`rounded-xl`) · 원형 `rounded-full`. 달력 카드 24px 는 앱의 주 표면으로 유일한 예외 | 컨트롤 8 / 10, 다이얼로그 10 / 14 |
| 주 버튼 | `Button` 기본 variant = 강조색. 색 class 를 붙이지 않음 | 강조색 / 갈색 / 검정 |
| 보조 · 위험 | 보조 `outline`, 되돌릴 수 없는 확인 `destructive`, 줄 안의 삭제 `ghost` + `text-destructive` | 각 3 · 3가지 |
| 버튼 너비 | 패딩은 size 가 정함 (`px` 덮어쓰기 금지). 다이얼로그 푸터 버튼은 최소 80px (`min-w-20`), 간격 `gap-2`, 오른쪽 정렬, 주 버튼이 맨 오른쪽 | 취소 `px-6` · 저장 `px-4`, 간격 2 / 3 |
| 버튼 안 아이콘 | 16px, 간격은 `Button` 의 `gap-2`. `mr-*` · `h-4 w-4` 를 붙이지 않음 | 간격 8 / 14 |
| 입력 너비 | 세로로 쌓인 폼은 `w-full`. 설정 행(라벨 왼쪽 · 컨트롤 오른쪽)의 컨트롤은 `w-60` 고정. 숫자 입력 `w-24` | 설정 선택 상자가 창 폭 전체, 숫자 `w-24` / `w-28` |
| 테두리 · 포커스 | 토큰만 (`border-input`, 3px `ring-ring/50`). 덮어쓰지 않음 | 테두리 4가지 · 링 4가지 |
| 다이얼로그 폭 | 확인형 `sm:max-w-md`, 폼형 `sm:max-w-lg`, 설정 창은 전용 | 업데이트 모달만 `lg` |
| 다이얼로그 푸터 | `border-t bg-muted/20 px-6 py-4` (본문과 구분되는 푸터를 쓰는 경우) | `muted/20` / `muted/10` |
| 글자 | 다이얼로그 제목 `text-lg font-semibold` · 설정 탭 제목 `text-2xl font-bold` · 소제목 `text-base font-bold` · 라벨 `text-sm font-medium` · 도움말 `text-xs text-muted-foreground` | 라벨 medium 16 / semibold 7 |
| 색 | 토큰만. `neutral-*` · hex 를 화면에 쓰지 않음 (창 버튼 hover 의 빨강은 예외) | 색 직접 지정 131곳 (그중 hex 9곳) |
| 부품 | `<button>` · `<input>` 대신 `Button` · `Input`. 예외: 색 견본, 창 버튼, `type="color"` | 직접 사용 22곳 |

## 영향 범위
- `apps/desktop/src/renderer/src`: `index.css`, `app.vue`, `components/*.vue`, `components/settings/*.vue`. 필요하면 `components/ui/button` 의 variant (생성 코드지만 프로젝트 소유).
- `apps/desktop/DESIGN.md` (새 파일), `AGENTS.md` 의 Conventions (프로젝트 영역) 한 줄.
- 영향 없음: main · preload · common, `packages/*`, `apps/server`, DB, i18n 문구, 확장 공개 API.

## 제약
- 기능 · 문구 · 레이아웃 구조는 그대로 둡니다. 크기와 모양만 맞춥니다.
- 확장이 그리는 화면은 호스트 CSS 토큰을 볼 수 있으므로, 기존 `--croffle-*` 토큰의 이름과 값은 바꾸지 않습니다.
- 라이트 / 다크 모두 확인합니다.
- rc.1 뒤의 안정화 작업 단위입니다. 새 기능을 넣지 않습니다.

### 에이전트가 정한 것
- 문서 위치는 `apps/desktop/DESIGN.md` 입니다. 대안은 `docs/design-system.md` 였는데, `docs/` 는 공개 문서(영어 + 한국어 사본) 자리이고 이 규칙은 데스크톱 렌더러에만 해당하므로 패키지 옆에 둡니다.
- 버전은 `1.3.0` 입니다 (rc.2 는 1.3.0 의 안정화 작업 단위).
- 조사 원본은 `.loctx/reports/1.3.0/rc2-ui-audit.md` 에 두고 retro 뒤 지웁니다. 규칙만 `DESIGN.md` 에 남깁니다.
- 강조색 위 흰 글자의 대비(약 2:1)는 지금도 같은 상태이고 색 체계 문제라 이번에 다루지 않고 로컬 로드맵에 적습니다.
