## 문제
서버 0.1.1 은 동기화 · 인증이 쓸 만해졌지만, 운영하기에는 아래가 부족합니다.

- **운영 작업은 CLI 로만 할 수 있습니다.** 계정 생성 · 비활성 · 비밀번호 재설정, 기기 토큰 발급 · 회수, 팀 멤버 추가, 서버 정보 · vacuum 은 모두 `docker exec … croffle-server <명령>` 입니다(`internal/cli/commands.go`). 대시보드(`apps/server/web`)는 로그인한 본인의 기기 · 팀(읽기) · 행 · 커밋 · 보안(OTP) 탭만 있습니다. 운영자 역할도 없습니다. `team_member.role` 열만 있고(`0001_init.sql`) 쓰이지 않습니다.
- **TOTP secret 이 평문으로 저장됩니다.** `account_otp.secret` 은 그대로 저장되며, 마이그레이션 주석에 "운영자가 관리하는 키가 필요해 이후 버전으로 미룬다"고 적혀 있습니다(`0005_otp.sql`, spec 003 우려 1).
- **팀은 하나뿐입니다.** `team-default` 하나가 마이그레이션으로 심어져 있고(`0001_init.sql`), CLI 의 팀 명령은 `list` · `add-member` 뿐입니다. pull 의 가시성 조건은 이미 여러 팀을 받지만(`store/sqlite/pull.go` `visibility`), 커서가 계정당 하나라서 새 팀에 들어가면 그 팀의 예전 행을 받지 못합니다. 코드 주석은 "팀별 커서는 다중 팀과 함께"라고 적고 있습니다(`pull.go:19–21`, 번호 재조정 전 표기 "0.3").

사용자 요청 (2026-11-16 · 17):
- "TOTP 암호화는 바로 다음버전으로 넣자." (2026-11-16)
- "TOTP도 있고, 지금 WebUI가 없다보니까 좀 불편해서 그래. v0.2.0을하고 desktop 밀고, 0.2.1로 할까?" (2026-11-17)
- "진행하자." (2026-11-17)

로컬 로드맵의 0.2.0 항목: "0.1을 넘어 쓸 수 있는 Vue UI, **다중 팀**, scope별 커서", "TOTP secret 암호화 … 운영자가 관리할 키(`CROFFLE_SECRET_KEY` 등)와 기존 평문 secret 이전이 필요".

## 바라는 결과
- 운영자가 CLI 없이 웹 대시보드에서 지금 CLI 가 하는 운영 작업을 모두 할 수 있습니다: 계정(생성 · 비활성 · 비밀번호 재설정 · OTP 해제), 기기 토큰(발급 · 회수), 팀 · 멤버, 서버 정보 · vacuum · 커밋 로그.
- 키를 설정한 서버에서는 TOTP secret 이 운영자가 관리하는 키로 암호화되어 저장됩니다. 이미 평문으로 저장된 secret 도 옮겨지며, 사용자는 OTP 를 다시 등록하지 않습니다. 키가 유출되면 운영자가 CLI 로 키를 바꿀 수 있습니다.
- 키가 없는 서버도 0.1.1 처럼 뜨고, 평문 저장이라는 경고를 시작 로그와 대시보드에 띄웁니다.
- 운영자가 팀을 여럿 만들고 멤버를 넣고 뺄 수 있습니다. 서버는 여러 팀을 동기화하며, 계정이 새 팀에 들어가면 그 팀의 기존 공유 행까지 받습니다.
- (2026-11-19 추가) 로그인한 사용자는 대시보드에서 자기 비밀번호를 바꿀 수 있습니다. 운영자가 임시 비밀번호로 만들어 준 계정을 받은 사람이 직접 바꿉니다.
- **배포된 데스크톱 1.3.0 · 1.3.1 은 아무것도 바꾸지 않아도 0.2.0 서버와 계속 동기화됩니다.** 다음 데스크톱 1.3.2(일정 공유)가 이 서버 위에 올라갑니다.

## 계획
1. **TOTP secret 암호화** — 운영자 키(`CROFFLE_SECRET_KEY` 또는 키 파일 `CROFFLE_SECRET_KEY_FILE`)로 `account_otp.secret` 을 암호화합니다(AEAD). 키가 설정된 서버는 시작할 때 평문 secret 을 암호화본으로 옮깁니다. 키가 없으면 평문으로 저장하고 시작 로그 · 대시보드에 경고를 띄웁니다(A3). 이전 키 → 새 키로 다시 암호화하는 CLI 명령을 둡니다(A4). 독립된 단위이고 보안 부채라 먼저 합니다.
2. **운영자 역할** — 계정에 운영자 여부를 두고, 첫 운영자를 정하는 방법(CLI)을 둡니다. 대시보드의 운영 API 는 운영자 세션만 받습니다.
3. **다중 팀 · 팀별 커서** — 운영자가 하는 팀 만들기 · 이름 바꾸기, 멤버 추가 · 제거(A2; CLI 와 운영 API), pull 커서를 팀(scope) 단위로 확장합니다. protocol 1 클라이언트가 보내는 커서 하나는 지금처럼 동작하고, 새 팀에 들어간 계정이 그 팀의 예전 행을 받는 방법은 spec 에서 정합니다(PM 해석: 선택 필드 또는 새 protocol 버전).
4. **대시보드 운영 화면** — 계획 2·3 위에, 지금 CLI 가 하는 운영 작업 전부를 Vue 화면으로 만듭니다(A1): 계정, 기기 토큰, 팀 · 멤버, 서버 정보 · vacuum · 커밋 로그. 본인 화면(기기 · 보안)은 유지합니다.
5. **문서 · 호환** — README(en · ko)의 운영자 · 키 · 팀 안내, 호환 표, 릴리스 노트 `docs/server/release/0.2.0.md`.
6. **본인 비밀번호 변경** (2026-11-19 추가) — 대시보드 보안 탭에서 지금 비밀번호(일회용 코드를 켰으면 코드도)를 확인하고 새 비밀번호로 바꿉니다. rc.1 뒤에 더하므로 rc.2 로 냅니다.

머지 뒤 audit → `server-v0.2.0-rc.1` 입니다.

## 영향 범위
- `apps/server/internal/{auth,httpapi,protocol,store/sqlite,cli,config}`, 새 SQL 마이그레이션(기존 것은 고치지 않음), 필요하면 `go.mod` · `go.sum`.
- `apps/server/web` (운영 화면).
- `packages/sync-fixtures` (팀별 커서 · 다중 팀 가시성 시나리오). 데스크톱 러너가 새 시나리오를 읽어야 하면 `apps/desktop/test/**`.
- `apps/server/README.md` · `README.ko.md`, `docs/server/release/0.2.0.md`.
- 영향 없음(PM 해석): 데스크톱 앱 코드(`apps/desktop/src/**`), `packages/types` · `packages/cli`, 데스크톱 릴리스.

## 제약
- **데스크톱 1.3.0 · 1.3.1 호환** — protocol 1 의 요청 · 응답 모양을 깨지 않습니다. 새 동작은 새 엔드포인트, 선택 필드, 또는 protocol 2 로만 열고, `/health` 의 `protocol.min` 은 1 로 둡니다.
- 바이너리 하나 · SQLite 하나. 키도 외부 서비스(KMS, Vault)를 요구하지 않습니다.
- 서버 의존성은 "검증된 소수 라이브러리 허용"이며, 새 의존성마다 spec 에 이유를 적습니다.
- 커밋된 SQL 마이그레이션은 고치지 않고 새 마이그레이션만 더합니다. `team-default` 는 지우지 않습니다(PM 해석: 기존 공유 행이 그 팀을 가리킴).
- 훅은 관찰 전용 · 비동기라는 0.1 결정을 지킵니다.
- `server-release` 는 GitHub Release 를 만들지 않습니다.
- 서버만 앞서는 버전입니다. 데스크톱이 팀을 고르거나 팀별 커서를 쓰는 작업은 이 intent 에 넣지 않습니다(데스크톱 1.3.2 이후).

### 에이전트가 정한 것
- 작업 순서: TOTP 암호화를 먼저 합니다. 다른 단위와 겹치지 않고 사용자가 "바로 다음버전으로"라고 한 보안 부채라서입니다. 대안은 운영 화면부터 하는 것이었습니다.
- 운영 화면은 운영자 역할과 다중 팀 위에 올리므로 계획의 뒤쪽에 둡니다.
- 버전 문자열은 `server-0.2.0`, 브랜치는 `feat/server-0.2.0` 입니다(0.1.1 과 같은 방식).
